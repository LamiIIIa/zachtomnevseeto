# Карта стилей форума

## Как CSS попадает на форум

```text
src/main.js
└── src/styles/main.css
    └── все CSS-модули в порядке @import
        └── Vite собирает их в dist/forum.css
```

`main.css` — единственная точка входа. Порядок импортов в нём важен: правила,
подключённые ниже, применяются позже и могут переопределять предыдущие.

## Структура папок

```text
src/styles/
├── main.css                 точка входа и порядок каскада
├── settings/                шрифты и общие CSS-переменные
├── themes/                  значения переменных для цветовых тем
├── generic/                 общие правила HTML-элементов
├── layout/                  каркас и крупные области форума
├── components/              повторно используемые элементы интерфейса
├── pages/                   стили конкретных страниц MyBB
├── responsive/              общая адаптация и медиазапросы
├── utilities/               маленькие служебные классы
└── legacy/                  снимки старого CSS, ожидающие переноса
```

## `settings/` — настройки проекта

| Файл | Что находится внутри |
| --- | --- |
| `fonts.css` | Подключение внешних шрифтов, включая `Bad Script` и `Klee One`, и наборов иконок. |
| `variables.css` | Общие размеры, шрифтовые переменные, отступы и другие значения `:root`. |

Новую общую переменную добавляй в `variables.css`. Цвет, который должен
меняться вместе с темой, добавляй во все файлы папки `themes/`.

## `themes/` — цветовые темы

| Файл | Что находится внутри |
| --- | --- |
| `base.css` | Значения, общие для всех тем. |
| `shinobi.css` | Тема «Даттебайо!». Также используется как основа админки. |
| `oto.css` | Тема «Я бессмертен!». |
| `akatsuki.css` | Тема «Познай боль!». |
| `green.css` | Тема «Сила Юности!». |
| `kakashi.css` | Тема «Как бы это сказать...». |

В этих файлах должны находиться преимущественно значения переменных, а не
полная разметка компонентов.

## `generic/` — общие правила элементов

| Файл | Что находится внутри |
| --- | --- |
| `links.css` | Базовое оформление ссылок и их состояний. |
| `browser.css` | Скроллбары и браузерные особенности. |
| `reset.css` | Ограниченный сброс стилей внутри `.forum-design`; админку не затрагивает. |

## `layout/` — крупный каркас

| Файл | Что находится внутри |
| --- | --- |
| `forum-frame.css` | Основной старый каркас страницы: `html`, `body`, `#pun`, `.punbb`, объявление и крупные блоки. |
| `forum-shell.css` | Новый общий каркас страниц форума. |
| `table-structure.css` | Общие правила старых таблиц и их строк. Не добавляй сюда новые карточки. |
| `footer.css` | Нижняя часть форума и `#pun-about`. |

## `pages/` — конкретные страницы

Файлы `*-base.css` — перенесённая основа старого дизайна. Одноимённые файлы
без `-base` — новый слой. Новый слой подключается позже и предназначен для
дальнейших правок.

| Файл | Страница и назначение |
| --- | --- |
| `index-base.css` | Старая основа содержимого главной страницы. |
| `index.css` | Новая главная: карточки, заголовки категорий и статистики, `.category-quote`, `.statistics-quote`. |
| `viewforum-base.css` | Старая основа страницы раздела. |
| `viewforum.css` | Новые правила страницы раздела `#pun-viewforum`. |
| `viewtopic.css` | Новые правила страницы темы `#pun-viewtopic`. |
| `profile-base.css` | Старая основа профиля. |
| `profile.css` | Новые правила профиля `#pun-profile`. |
| `userlist-base.css` | Старая основа списка участников. |
| `userlist.css` | Новые правила списка участников `#pun-userlist`. |
| `messages-base.css` | Старая основа личных сообщений. |
| `messages.css` | Новые правила личных сообщений `#pun-messages`. |
| `admin.css` | Отдельные исправления панели администратора. |

## `responsive/` — адаптивность

| Файл | Что находится внутри |
| --- | --- |
| `theme.css` | Общие медиазапросы, исправления Firefox и адаптация старого дизайна. |

Стили мобильной версии конкретного нового компонента можно хранить рядом с
ним. В `responsive/theme.css` следует добавлять только правила, затрагивающие
сразу несколько страниц или компонентов.

## `utilities/` — служебные классы

| Файл | Что находится внутри |
| --- | --- |
| `visibility.css` | Универсальный класс `.hidden`. |
| `content-visibility.css` | Системные скрытия элементов MyBB и исключения для модальных окон. |

## `legacy/` — старые снимки

| Файл | Статус |
| --- | --- |
| `header-external.css` | Снимок внешнего CSS шапки; пока подключён первым в `main.css`. |
| `extra.css` | Снимок старого `extra.css`; пока подключён перед новым слоем. |
| `mobile.css` | Снимок встроенного мобильного CSS MyBB. Хранится для справки и **не импортируется**, потому что MyBB загружает его самостоятельно. |

Старый полный дизайн дополнительно хранится вне рабочей папки стилей:

```text
src/legacy/styles/theme.css
src/legacy/styles/admin-main.css
```

Эти два файла не импортируются в `main.css` и не попадают в `forum.css`.

## Куда добавлять новое правило

| Задача | Файл или папка |
| --- | --- |
| Только главная страница | `pages/index.css` |
| Только страница раздела | `pages/viewforum.css` |
| Только страница темы | `pages/viewtopic.css` |
| Только профиль, участники или сообщения | соответствующий файл в `pages/` |
| Один компонент на нескольких страницах | `components/` |
| Общий каркас страницы | `layout/` |
| Общая переменная | `settings/variables.css` |
| Значение, меняющееся между темами | все нужные файлы в `themes/` |
| Скрытие элемента через класс | `utilities/visibility.css` |
| Глобальная адаптация нескольких страниц | `responsive/theme.css` |

## Правило миграции старого CSS

1. Найди старое правило в `legacy/` или в файле `*-base.css`.
2. Определи, относится оно к странице, компоненту или каркасу.
3. Перенеси правило в соответствующий новый файл без `-base`.
4. Замени общий старый селектор на класс, добавленный JavaScript-кодом.
5. Удали исходный дубликат, если он больше нигде не используется.
6. Проверь `npm run build` и страницу форума на обычной и мобильной ширине.
