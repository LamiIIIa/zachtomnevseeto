# Быстрый предпросмотр при редактировании

Парсер BBCode сохранён. Убрано условие, запрещавшее обработку поля внутри .post. Контроллер выбирает активное поле сообщения и использует единый post-preview, переносит его к активной форме. Повторные input/change обрабатываются с задержкой 40 мс; кнопки редактора запускают обновление после изменения значения через JavaScript. События pun_preedit/pun_edit/pun_post и замена textarea также поддержаны.

Кнопка работает на отдельной странице и в AJAX-редакторе. Состояние хранится в _PreviewToggle; выключение скрывает предпросмотр, не заменяя глобальный ParseContent пустой функцией. При включении всегда показывается последний введённый текст. Старый inline-wrapper setCookiePPrev/togglePreview заменяется при публикации вызовом refresh — две реализации кнопки одновременно не запускаются.

Обработчик вкладок предпросмотра устанавливается с namespace и не накапливается при каждом вводе. Поля внутри предпросмотра и служебной формы масок не выбираются как редактор.

Проверка: node scripts/post-preview-edit.test.mjs — отдельная страница и поле внутри поста, несколько изменений подряд, отключение/включение, программная вставка, замена textarea, повторное открытие с выключенным предпросмотром.
