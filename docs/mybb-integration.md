# Что оставить в полях MyBB после сборки проекта

Логика из актуальных полей основного форума перенесена в модули `src/`. Удалять
старые вставки с форума нужно только после того, как новая сборка `forum.js` и
`forum.css` появилась на GitHub Pages.

## HTML-верх

Оставить:

- короткий ранний скрипт применения сохранённой темы — он предотвращает мигание
  старой темы до загрузки `forum.js`;
- `noscript`-защиту;
- PR-вход и его настройки: пароль должен оставаться только в панели MyBB и не
  должен попадать в публичный репозиторий;
- сторонние плагины уведомлений, репутации, аватара в цитатах, быстроплюсов и
  масок, пока они используются;
- два загрузчика тестовых `forum.css` и `forum.js`.

Ранний скрипт должен стоять **до загрузчика `forum.js`**. Он сразу окрашивает
корень страницы в цвет сохранённой темы и убирает белую вспышку во время
перезагрузки:

```html
<script>
(function () {
  var themes = ['shinobi', 'oto', 'akatsuki', 'green', 'kakashi'];
  var backgrounds = {
    shinobi: '#fbf2e5',
    oto: '#e9e9e9',
    akatsuki: '#f5f1f1',
    green: '#fcf4ed',
    kakashi: '#363636'
  };
  var storedTheme;

  try {
    storedTheme = localStorage.getItem('selectedTheme');
  } catch (error) {
    storedTheme = null;
  }

  var theme = themes.indexOf(storedTheme) !== -1 ? storedTheme : 'shinobi';
  var root = document.documentElement;

  root.classList.remove.apply(root.classList, themes);
  root.classList.add(theme);
  root.style.backgroundColor =
    'var(--color-forum, ' + backgrounds[theme] + ')';
})();
</script>
```

После публикации новой сборки можно удалить разметку `.go-up`/`.go-down` и
связанный с ней jQuery-скрипт. Кнопки теперь создаёт
`src/components/scroll-controls.js`.

## Объявление

Оставить всю разметку шапки: `.table`, `.leftparp`, ссылки, администраторов,
`.newsbox` и `.nvsscroll`.

Удалить встроенный скрипт переключения тем. Пустой список
`<ul id="theme_switcher"></ul>` оставить — его заполняет проект.

Новости загружает `src/components/header/news.js`. По умолчанию тестовик, как и
раньше, получает тему `86` основного форума. Чтобы использовать другую тему или
локальный API тестовика, достаточно написать:

```html
<div class="nvsscroll" data-api-url="/api.php" data-topic-id="7"></div>
```

Ссылки внутри объявления остаются такими, как они записаны в MyBB. Это важно
для тестовика: ID его тем отличаются, поэтому актуальные ссылки продолжают
вести на соответствующие страницы основного форума.

## HTML-низ

После обновления сборки можно удалить старые блоки:

- подписи `title` для системных элементов;
- аватар по умолчанию;
- DICE;
- сохранение черновиков в `localStorage`;
- News;
- RADAR;
- запрет редактирования профиля для группы `6`.

Их заменяют соответственно:

- `src/components/forum-elements.js`;
- `src/components/editor/index.js`;
- `src/components/header/news.js`;
- `src/components/radar.js`.

Разметку `.bannerc` с партнёрскими баннерами оставить: это контент форума, а
проект только перемещает и оформляет его. Сторонние скрипты предпросмотра,
обновления тем, аватара в цитатах и прочие плагины `forumstatic.ru` также пока
оставить. Старую автоматическую разбивку постов на абзацы тоже пока оставить:
она меняет пользовательскую разметку и требует отдельной проверки на сложных
BB-кодах.

## Форма ответа

После обновления сборки можно удалить:

- старый счётчик символов;
- код создания кнопки кубиков;
- блок дополнительных цветов;
- `FORUM.set("editor.link.short_url", ...)`;
- скрипт взаимной рекламы;
- встроенные скрытия `.pl-reports` и RSS — они уже есть в общем CSS.

Загрузчик дополнительного набора смайлов оставить: это отдельный сторонний
плагин и его файл данных.

## Пользовательские BB-теги

Определение тега должно остаться в панели MyBB, потому что замену BB-кода
выполняет движок:

```text
[radar]{1}[/radar]
<div class="radar-wrapper" data-stats="{1}"></div>
```

Построение SVG и стили диаграммы теперь находятся в проекте. Дополнительно
поддерживаются старые варианты `[radar=1,2,...]` и
`[radar]1,2,...[/radar]`.
