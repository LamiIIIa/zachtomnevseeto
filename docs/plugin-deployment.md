## Частые обновления

1. Изменить рабочий источник соответствующего модуля и выполнить его сборщик. Для боёвки это `mubb-battle-assistant.source.js` и `build-battle-assistant.mjs`; для поиска — последний script в `mubb-technique-search.html` и `build-technique-search.mjs`. У магазина/галереи использовать их существующие исходники и сборщики, не старые комплекты из `output/`.
2. Из корня рабочей папки запустить `node forum-assets-sync/scripts/import-workspace-plugins.mjs`. Команда копирует только четыре названных загрузочных файла в `forum-assets-sync/src/plugins/` под теми же именами. Она не коммитит и не публикует ничего сама.
3. Проверить изменения именно в `forum-assets-sync`, собрать `npm run build:local` и выполнить необходимые проверки. Не добавлять в Git HTML-снимки админки, HAR, токены, cookies, `.env` или всю рабочую папку.
4. Сделать коммит и push в `main` репозитория публикации. Workflow `Publish local forum assets` проверяет сборку, входит через GitHub Actions Secrets и обновляет содержимое постоянных файлов через редактор форума. URL сохраняет числовое имя, `?v=` берётся из новой версии файла. Повторный запуск без изменений не создаёт копии.
5. Дождаться успешного workflow. Локальная сборка и импорт без коммита ничего на форуме не меняют. При обнаружении ручной правки файла на форуме после предыдущей публикации пайплайн останавливается, не затирая её: сначала перенести обновление в Git. Это защищает частые доработки от возврата старой копии при коммите только стилей.

Снимки четырёх загрузочных JS хранятся в Git. История версий ведётся Git, а не россыпью активных файлов на форуме. Частная конфигурация HTML-форм сохраняется только на форуме и подменяется точечно при публикации.

`scripts/prepare-plugins.mjs` применяет технические адаптации во время сборки: убирает повторный импорт полного дизайна с GitHub из магазина, сохраняет кнопки внутри формы ответа и ограничение групп, отключает скачивание всех картинок галереи заранее. Бизнес-логику не править в этих адаптациях. При существенном изменении структуры галереи сборка останавливается для проверки адаптера вместо молчаливой публикации сломанного кода.

## Условия подключения

- Магазин скачивается только в `viewtopic.php?id=202`; корневой пост — `2235`.
- Боёвка и поиск техник скачиваются только при наличии формы ответа/редактирования и только группам `1` (Администраторы), `2` (Модераторы), `5` (Игроки). Кнопки находятся внутри формы. Глобальные кнопки над страницей не добавлять. Без формы файлы не загружать, включая скрытые iframe.
- Необязательные плагины ждут оформления. Галерея читает тему `214`, активируется у своей области и загружает только видимые изображения; публикация новых персонажей не требует ручного изменения JS или сообщений.
- Старые прямые script-подключения этих модулей не дублировать рядом с управляемыми `data-forum-plugin` дескрипторами. При смене версии пайплайн меняет URL в дескрипторе автоматически.

## Архив и удаление

`fd-plugin-*` — прежние автоматически созданные копии; после переключения они получают тег `Архив` и тег модуля. Пайплайн не удаляет файлы автоматически. Архивная копия не должна подключаться в актуальном HTML-верхе/низе.

Удалять загрузки на форуме вручную можно после проверки, что их URL отсутствуют в формах, страницах и сообщениях, где файл мог быть установлен отдельно. Сначала ориентироваться на тег `Архив`, затем проверить ссылки. Сам по себе возраст/меньший номер версии не доказывает, что файл не нужен. Постоянные четыре файла из таблицы, активный CSS/JS дизайна, шрифты и изображения не удалять как «дубликаты».

Удаление локальных `.source`, сборщиков или Git-репозитория на компьютере не является очисткой загрузок форума: это рабочие материалы для следующих обновлений. Снимки и исторические пакеты из `output/` можно удалять отдельно, если они не нужны для восстановления.

## Автоматические файлы дизайна

Все автоматически опубликованные файлы дизайна помечаются `GitHub`, `Дизайн` и типом файла. Не подключённые старые CSS/JS получают `Архив`; отчёт `file-audit` сохраняется в артефактах Actions. Файлы автоматически не удаляются: перед ручным удалением проверяются также отдельные страницы и сообщения. Шрифты и изображения сохраняются консервативно.
