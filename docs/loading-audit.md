# Загрузка форума: разбор и новая схема

Проверены актуальные HTML-верх/низ и HAR от 31.10.2026. Приватные HTML-снимки и HAR остаются вне репозитория. Последний исходный замер пользователя: DOMContentLoaded 4,24 с, Load 4,65 с, 11,23 МБ передано.

## Причина задержки HTML

Обычные script без async/defer останавливают парсер до загрузки и выполнения. Дополнительно старые загрузчики уведомлений, репутации, realtime и PR-входа используют document.write для подключения следующего файла. Динамические модули/стили обнаруживаются последовательно. Скрипт дизайна с defer ожидает окончания разбора всего документа, хотя сам файл уже скачан. В исходном HAR дизайн получен к 1,26 с, а DOMContentLoaded наступает в 4,24 с.

Проблема не в количестве HTML-таблиц как таковом. Для главной уже действует раннее оформление карточек; заглушка загрузки и скрытие всей страницы не используются.

## Дополнения после оформления и window.load

`scripts/deferred-extras.mjs` заменяет только известные необязательные подключения на неисполняемые JSON-дескрипторы. После готовности дизайна и основной загрузки браузер получает два кадра на отрисовку, параллельно скачивает подходящие файлы и исполняет их в исходном порядке. Inline-настройки, включая приватную конфигурацию PR-входа, сохраняются на форуме, а не в Git. Закомментированные подключения не включаются.

Для старых дополнений сохранены авторские исходники и лицензии в `src/plugins/compat/`. У цитат и предпросмотра document.write добавлял только стили: они вставляются безопасно в head. Обработчики цитат и инициализация масок выполняются после зависимостей, даже если DOMContentLoaded уже прошёл. Предпросмотр и кнопки остаются внутри штатной формы.

Не загруженные ранее виджеты могут появиться через AJAX: наблюдатель проверяет соответствующие условия и запускает их один раз. Нет глобальных кнопок боёвки/поиска. Их существующая схема дополнительно ждёт окончания обработки контента и сохраняет ограничения формы и групп.

## Проверки и измерение

- `prepaint.test.mjs`: реальное оформление до задержанного JS на мобильных/desktop ширинах, без промежуточной таблицы и заглушки.
- `background-plugins.test.mjs`: группы 1/2/5, только форма ответа, поздняя форма, тема магазина, отсутствие второго CSS, видимые картинки галереи.
- `deferred-extras.test.mjs`: уведомления неизменны и запускаются приоритетно; исходный порядок зависимостей; закомментированные теги; условные и поздние виджеты; реальные старые jQuery/цитаты/предпросмотр; выбор постоянных файлов.
- Публикация проверяет живые главную и тему с формой ответа, доступность notifications/realtime и ошибки дополнений. Замер до/после выполняется в одном CI runner с отключённым кешем и одинаковым сетевым фильтром. Это контрольный серверный браузер, а не подмена замера с устройства пользователя.

## Галерея: варианты без ручного изменения сообщений

Текущий вариант уже не скачивает все десять оригиналов заранее. Тем не менее пять видимых PNG в HAR занимают 6,55 МБ; одна картинка — 3,11 МБ. Загрузка по видимости не уменьшает сам файл. Для следующего этапа нужны автоматические миниатюры.

1. **Vercel Image Optimization по запросу.** Галерея передаёт исходный URL из темы в разрешённый обработчик, который отдаёт уменьшенное изображение; Vercel кеширует преобразования. Указывать разрешённые хосты/пути, фиксированные размеры и качество. Тема остаётся источником данных, ручная замена сообщений не нужна. Браузер обращается к Vercel для изображений, поэтому доступность этого пути из нужного подключения следует проверить.
2. **Готовые миниатюры в Vercel Blob.** Сервер читает тему, автоматически преобразует новые/изменённые изображения и сохраняет результат под именем по хешу. Галерея получает маленький JSON-манифест `URL оригинала → URL миниатюры`. Постоянные изображения обслуживаются без повторного преобразования; замены по хешу не оставляют старое изображение в кеше.
3. **Обработка на сервере, раздача с форума.** Vercel либо задача CI генерирует миниатюры и загружает их на forumstatic.ru. Посетители продолжают получать картинки из файлов форума; дополнительный сервис не участвует в показе страницы. Нужен автоматический запуск при изменениях темы либо регулярная проверка её содержимого. Один только коммит не обнаружит новый пост или правку старого сообщения.

Предпочтительный вариант для сохранения локальной раздачи — №3; №2 проще отделяет обработку от файлов форума. Обязательно учитывать правки старых сообщений и замену изображения по прежнему URL, а не только максимальный ID поста. Преобразование на клиенте через canvas всё равно требует скачать большой оригинал и не решает первый визит.

Документация: [Vercel Image Optimization](https://vercel.com/docs/image-optimization), [Vercel Blob](https://vercel.com/docs/vercel-blob). На этом этапе сервис Vercel и хранилище не создаются: варианты предложены отдельно от оптимизации загрузки форума.
